Exemplo 6 — cliente D-Bus: bateria via UPower

Um cliente completo: lê a propriedade Percentage do UPower e fica escutando PropertiesChanged — o indicador de bateria da barra, sem polling.

// Cargo.toml:
// [dependencies]
// zbus = { version = "4", features = ["tokio"] }
// tokio = { version = "1", features = ["full"] }
// futures = "0.3"

use futures::StreamExt;
use zbus::proxy;

// derive que gera o proxy tipado a partir da interface D-Bus
#[proxy(
    interface = "org.freedesktop.UPower.Device",
    default_service = "org.freedesktop.UPower",
    default_path = "/org/freedesktop/UPower/devices/DisplayDevice"
)]
trait UPowerDevice {
    #[zbus(property)]
    fn percentage(&self) -> zbus::Result<f64>;

    #[zbus(property)]
    fn state(&self) -> zbus::Result<u32>;  // 1=carregando, 2=descarregando, 4=cheia
}

#[tokio::main]
async fn main() -> zbus::Result<()> {
    // DisplayDevice = a soma de todas as baterias
    let conn = zbus::Connection::system().await?;   // UPower vive no SYSTEM bus
    let bateria = UPowerDeviceProxy::new(&conn).await?;

    println!("bateria: {:.1}%", bateria.percentage().await?);

    // PropertiesChanged como Stream — dispara quando a propriedade muda
    let mut changes = bateria.receive_percentage_changed().await;
    while let Some(change) = changes.next().await {
        let novo = change.get().await?;
        println!("bateria mudou: {novo:.1}%");
        // no shell: tx.send(Evento::Bateria { ... })
    }
    Ok(())
}
  • #[proxy] gera UPowerDeviceProxy em compilação — methods viram async fn, properties viram getters + stream de mudanças. É o ? de tipagem: erros de nome de interface aparecem em compilação.
  • Session bus para apps (notifications), system bus para serviços de máquina (UPower, NetworkManager, BlueZ) — por isso Connection::system() aqui.

Para explorar o D-Bus REAL da sua sessão antes de codificar:

busctl introspect org.freedesktop.UPower /org/freedesktop/UPower/devices/DisplayDevice

Exemplo 7 — servidor D-Bus: o daemon de notificações

Aqui o papel inverte: o shell exporta a interface org.freedesktop.Notifications e os apps chamam você. Com zbus, o serviço é um struct comum.

use std::collections::HashMap;
use std::sync::atomic::{AtomicU32, Ordering};
use std::sync::mpsc::Sender;
use zbus::zvariant::Value;

pub struct Notificacao {
    pub app: String,
    pub titulo: String,
    pub corpo: String,
}

pub struct NotificationServer {
    tx: Sender<Notificacao>,          // manda para o event bus do shell
    proximo_id: AtomicU32,
}

// "exporta" o struct como interface D-Bus
#[zbus::interface(name = "org.freedesktop.Notifications")]
impl NotificationServer {
    fn notify(
        &self,
        app_name: &str,
        replaces_id: u32,               // >0 = substituir notificação existente
        _app_icon: &str,
        summary: &str,
        body: &str,
        _actions: Vec<&str>,
        _hints: HashMap<&str, Value<'_>>,
        expire_timeout: i32,            // -1 = padrão do servidor, 0 = nunca expira
    ) -> u32 {
        let id = self.proximo_id.fetch_add(1, Ordering::SeqCst);
        let _ = self.tx.send(Notificacao {
            app: app_name.into(),
            titulo: summary.into(),
            corpo: body.into(),
        });
        id                              // o chamador guarda o id p/ fechar depois
    }

    fn get_capabilities(&self) -> Vec<String> {
        vec!["body".into()]             // declare só o que sua UI suporta
    }

    fn get_server_information(&self) -> (String, String, String, u32) {
        ("meushell".into(), "eu".into(), "0.1.0".into(), 1)
    }

    fn close_notification(&self, _id: u32) {
        // emitir Evento::FecharNotificacao no bus
    }
}

#[tokio::main]
async fn main() -> zbus::Result<()> {
    let (tx, _rx) = std::sync::mpsc::channel();
    let conn = zbus::Connection::session().await?;   // apps usam o SESSION bus

    conn.object_server().at(
        "/org/freedesktop/Notifications",
        NotificationServer { tx, proximo_id: AtomicU32::new(1) },
    ).await?;

    // disputa o nome — o daemon anterior deve liberar (spec obriga!)
    conn.request_name("org.freedesktop.Notifications").await?;

    // segura a conexão viva para sempre
    futures::future::pending::<()>().await;
    Ok(())
}
  • Desktop Notifications Spec — leia a seção do protocolo: os 3 methods e os hints documentados
  • zbus book — capítulo de servidores (o #[interface] e object_server)
  • Teste sem UI: notify-send "teste" "corpo" deve acionar seu notify()
