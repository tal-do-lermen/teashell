Arquitetura interna

Como organizar um app de longa duração com vários subsistemas independentes — é aqui que tudo que você aprendeu de Rust (threads, canais, traits, ownership) vira design.

O esqueleto

Estude esta arquitetura:

Wayland Event Loop
        ↓
Application State
        ↓
Message/Event Bus
        ↓
Modules

Em termos do que você já conhece: um loop de eventos (como rx.recv().await do capítulo async), um estado central protegido, um canal distribuidor e módulos como consumidores/produtores de eventos.

Evite criar um grande estado global compartilhado por todos os módulos (o singleton tentador de quem vem de Java). Em Rust isso vira briga com Arc<Mutex> em todo lugar. Prefira: cada módulo com seu estado, comunicação por eventos, e o mínimo de compartilhamento.

O princípio central

A ideia principal é evitar que os componentes de UI conheçam diretamente detalhes de D-Bus ou Wayland.

Na prática, com dependency inversion:

  • A Bar conhece enum Evento e struct EstadoAudio — nunca zbus::Proxy.
  • O módulo D-Bus traduz signals de PipeWire em Evento::VolumeMudou(f64).
  • O módulo Wayland traduz teclas em Evento::Tecla(...).
  • Testar a UI não exige Wayland nem D-Bus: envie eventos falsos (as mocks saem de graça com enums).
enum Evento {
    Wayland(EventoWayland),
    Audio(EventoAudio),
    Rede(EventoRede),
    Config(EventoConfig),
    Ipc(Comando),
}

Exemplo 5 — o event bus em código

Este é o coração do shell: um canal mpsc (você já fez um no capítulo de concorrência) com módulos conectados por trait — nada de estado global.

use std::sync::mpsc::{channel, Receiver, Sender};

// Eventos do shell — a ÚNICA coisa que os módulos compartilham
#[derive(Debug, Clone)]
pub enum Evento {
    Tick,
    Volume { nivel: f64, mute: bool },
    Bateria { percentual: u8, carregando: bool },
    Tecla { code: u32 },
    Idle,
    Redesenhar,
    Comando(Comando),
}

#[derive(Debug, Clone)]
pub enum Comando {
    ToggleLauncher,
    Reload,
    Lock,
    Quit,
}

// Contrato dos módulos: entram eventos, saem eventos
pub trait Modulo {
    fn nome(&self) -> &'static str;
    fn handle(&mut self, evento: &Evento, saida: &Sender<Evento>);
}

pub struct Bus {
    tx: Sender<Evento>,
    rx: Receiver<Evento>,
}

impl Bus {
    pub fn novo() -> Self {
        let (tx, rx) = channel();
        Self { tx, rx }
    }

    // cada produtor (wayland, dbus, ipc) guarda um clone deste tx
    pub fn tx(&self) -> Sender<Evento> {
        self.tx.clone()
    }

    // roda numa thread dedicada até chegar Comando::Quit
    pub fn rodar(mut self, mut modulos: Vec<Box<dyn Modulo>>) {
        while let Ok(evento) = self.rx.recv() {
            if matches!(evento, Evento::Comando(Comando::Quit)) {
                break;
            }
            for m in &mut modulos {
                m.handle(&evento, &self.tx);
            }
        }
    }
}

// um módulo de exemplo — repare: ele NÃO conhece zbus nem wayland
pub struct ModuloNotificacoes;

impl Modulo for ModuloNotificacoes {
    fn nome(&self) -> &'static str { "notificações" }

    fn handle(&mut self, evento: &Evento, saida: &Sender<Evento>) {
        if let Evento::Comando(Comando::ToggleLauncher) = evento {
            // decidir, emitir, seguir — sem bloquear os outros módulos
            let _ = saida.send(Evento::Redesenhar);
        }
    }
}

// let bus = Bus::novo();

// iniciar_wayland(tx.clone())?;    // produtor
// iniciar_dbus(tx.clone())?;       // produtor
// iniciar_ipc(tx)?;                // produtor

Por que isto funciona:

  • tx.clone() por produtor, um único rx no bus — o padrão mpsc do capítulo 7.
  • Box<dyn Modulo> é o dyn Trait do capítulo 4: polimorfismo em runtime, cada módulo testável isoladamente com eventos falsos.
  • Módulos não compartilham struct nenhuma: só conversam por eventos (actor/observer). Config compartilhada? Vira evento ConfigAtualizada(Config) ou um Arc<RwLock<Config>> — nunca um mutex global solto.
  • A versão async (tokio mpsc + .await) é idêntica em forma — você viu o esqueleto no capítulo async.

  • tokio::sync::mpsc — a versão async do mesmo canal
  • Actor model — o nome acadêmico do que este código faz
