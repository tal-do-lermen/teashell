Configuração, IPC e performance

A infraestrutura que amarra o shell: arquivo de config com hot reload, um socket de comandos, e a disciplina de performance para um app que roda o dia inteiro.

Configuração

Pesquise:

  • Serde
  • TOML
  • XDG Base Directory
  • XDG config directory
  • Config validation
  • Config reload
  • File watching

Rust:

  • serde
  • toml
  • notify

Estrutura conceitual:

config.toml
      ↓
parser
      ↓
validation
      ↓
application state

Para hot reload:

arquivo alterado
      ↓
watcher
      ↓
parse
      ↓
validate
      ↓
apply

Com serde, struct Config deriva Deserialize e o parse + validação viram: toml::from_str::<Config>(&texto)? seguido de uma função validate(&config) -> Result<()> sua. Se a validação falhar no hot reload: logue o erro e mantenha a config antiga — nunca deixe o shell quebrar porque alguém salvou um TOML incompleto.

Performance

Como o shell ficará sempre executando, performance deve ser estudada desde o começo.

Pesquise:

  • Linux perf
  • cargo flamegraph
  • Flamegraphs
  • Heap profiling
  • Allocation profiling
  • GPU profiling
  • RenderDoc
  • Sysprof
  • strace
  • bpftrace
  • eBPF
  • criterion — benchmarks com estatística
  • tracing — spans medem o seu próprio código

Para Wayland:

  • Frame callbacks
  • Damage tracking
  • Partial redraw
  • Dirty regions
  • Frame pacing
  • VSync
  • Input latency
  • GPU synchronization

Evite uma arquitetura baseada em:

loop
  ↓
sleep(16ms)
  ↓
redraw everything

Prefira:

event
 ↓
state changed?
 ↓
damage
 ↓
render
 ↓
frame callback
 ↓
wait

É o mesmo princípio de um framework reativo: só redesenhe o que mudou, só quando houver frame callback pedindo. O sleep manual queima CPU sem melhorar nada — o frame callback já sincroniza com o refresh do monitor.

Exemplo 12 — config com serde + hot reload

// Cargo.toml:
// [dependencies]
// serde = { version = "1", features = ["derive"] }
// toml = "0.8"
// anyhow = "1"

use anyhow::{bail, Context, Result};
use serde::Deserialize;
use std::path::Path;

#[derive(Debug, Deserialize)]
#[serde(deny_unknown_fields)]        // typo na config vira erro na hora certa
pub struct Config {
    pub bar: Bar,
}

#[derive(Debug, Deserialize)]
pub struct Bar {
    pub altura: u32,
    #[serde(default = "default_fonte")]
    pub fonte: String,
    #[serde(default)]
    pub mostrar_bateria: bool,
}

fn default_fonte() -> String { "monospace 12".into() }

// parser -> validation -> application state (o fluxo do diagrama acima)
pub fn carregar(caminho: &Path) -> Result<Config> {
    let texto = std::fs::read_to_string(caminho)
        .with_context(|| format!("lendo {}", caminho.display()))?;
    let config: Config = toml::from_str(&texto).context("parseando config")?;
    validar(&config)?;
    Ok(config)
}

fn validar(c: &Config) -> Result<()> {
    if c.bar.altura == 0 || c.bar.altura > 200 {
        bail!("bar.altura deve estar entre 1 e 200");
    }
    Ok(())
}

Hot reload com notify — o watcher roda numa thread própria e fala com o bus por eventos (veja o Exemplo 5):

// Cargo.toml: notify = "8"
use notify::{Event, RecursiveMode, Watcher};
use std::sync::mpsc::{channel, Sender};
use std::time::Duration;

fn observar(caminho: std::path::PathBuf, tx: Sender<Evento>) -> notify::Result<()> {
    let (event_tx, event_rx) = channel();
    let mut watcher = notify::recommended_watcher(move |res: Result<Event, _>| {
        if res.is_ok() {
            let _ = event_tx.send(());
        }
    })?;
    watcher.watch(&caminho, RecursiveMode::NonRecursive)?;

    std::thread::spawn(move || {
        while event_rx.recv().is_ok() {
            // debounce: editores salvam várias vezes seguidas
            while event_rx.recv_timeout(Duration::from_millis(300)).is_ok() {}

            if let Ok(config) = carregar(&caminho) {
                let _ = tx.send(Evento::ConfigAtualizada(config));
            } else {
                // config quebrada: logue e MANTENHA a anterior rodando
            }
        }
    });
    Ok(())
}

  • docs.rs/anyhow — context/bail do capítulo de erros

Exemplo 13 — IPC: unix socket + CLI

use std::io::{BufRead, BufReader, Write};
use std::os::unix::net::UnixListener;
use std::path::Path;
use std::sync::mpsc::Sender;

// protocolo mínimo: 1 comando por linha, 1 resposta por linha
pub fn servir(sock_path: &Path, tx: Sender<Comando>) -> Result<(), Box<dyn std::error::Error>> {
    let _ = std::fs::remove_file(sock_path);    // sobra de execução anterior
    let listener = UnixListener::bind(sock_path)?;

    for stream in listener.incoming() {
        let mut stream = stream?;
        let mut reader = BufReader::new(stream.try_clone()?);
        let mut linha = String::new();
        reader.read_line(&mut linha)?;

        match linha.trim() {
            "reload" => { tx.send(Comando::Reload)?; stream.write_all(b"ok\n")?; }
            "toggle-launcher" => { tx.send(Comando::ToggleLauncher)?; stream.write_all(b"ok\n")?; }
            "lock" => { tx.send(Comando::Lock)?; stream.write_all(b"ok\n")?; }
            "quit" => { tx.send(Comando::Quit)?; stream.write_all(b"bye\n")?; }
            outro => { stream.write_all(format!("erro: '{outro}'\n").as_bytes())?; }
        }
    }
    Ok(())
}

E o CLI que controla o shell — um segundo binário no mesmo projeto:

// src/bin/meushell-cli.rs (cargo compila os dois)
use std::io::{BufRead, BufReader, Write};
use std::os::unix::net::UnixStream;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let cmd = std::env::args().nth(1).expect("uso: meushell-cli <comando>");
    let dir = std::env::var("XDG_RUNTIME_DIR")?;
    let mut stream = UnixStream::connect(format!("{dir}/meushell.sock"))?;

    writeln!(stream, "{cmd}")?;
    let mut resposta = String::new();
    BufReader::new(stream).read_line(&mut resposta)?;
    println!("{}", resposta.trim());
    Ok(())
}
  • O socket em $XDG_RUNTIME_DIR/meushell.sock herda as permissões do diretório — só o seu usuário conecta (segurança de graça).
  • tx.send(...) joga o comando no event bus — o IPC é só mais um produtor, igual ao Wayland e ao D-Bus.
  • Upgrade natural: JSON-RPC (crate serde_json) para respostas ricas (query state), ou a versão async com tokio::net::UnixListener.
  • unix(7) — Unix domain sockets
  • tokio::net::UnixListener — versão async do mesmo listener
  • Para protocolo decente: JSON-RPC 2.0 spec + serde_json
