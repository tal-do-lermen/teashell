O que NÃO estudar primeiro

Não comece por:

  • Smithay internals
  • DRM/KMS
  • compositor implementation
  • XWayland internals
  • wlroots internals
  • GPU driver development

Esses assuntos são muito importantes para um compositor Wayland, mas não são necessários para o primeiro estágio de um desktop shell. Se posteriormente o objetivo for criar seu próprio compositor/WM em Rust, aí sim eles passam a ser centrais.

O SEU ambiente, agoraferramentas de inspeção — ver abaixo

Ferramentas de inspeção (use antes de codificar)

FerramentaO que revela
wayland-info (pacote wayland-utils)os globals que o SEU compositor suporta — a lista de protocolos disponíveis para o shell
busctl --user tree / busctl introspect <serviço> <objeto>os objetos, métodos, properties e signals reais do D-Bus da sua sessão
busctl --system ...o system bus (UPower, NetworkManager, BlueZ)
d-feet ou qdbusviewer (GUI)mesma coisa do busctl, clicável
ls ~/.local/share/applicationsos .desktop reais para testar seu parser
cat /sys/class/backlight/*/brightnesso backlight real do seu hardware

Hábito que acelera tudo: antes de implementar qualquer integração, inspecione o serviço real (wayland-info, busctl, os arquivos .desktop) e só depois leia a spec/docs. Ver o dado real primeiro transforma documentação abstrata em algo concreto.
