O campo Exec tem regras próprias de escaping e códigos de campo (%f, %u…). Pesquise parsing seguro de argumentos — não use sh -c com a string crua.

Workspaces e janelas

Pesquise os protocolos:

  • wlr-foreign-toplevel-management — listar/controlar janelas (Sway, Hyprland)
  • ext-workspace-v1 — workspaces como protocolo padrão
  • ext-foreign-toplevel-list-v1 — listar janelas (protocolo padrão)

Entenda:

  • listar janelas
  • detectar janela ativa
  • minimizar/maximizar quando suportado
  • fechar
  • focar
  • workspace atual
  • mover janela
  • acompanhar eventos

Também pesquise APIs específicas de:

  • Sway IPC
  • Hyprland IPC
  • Niri IPC

Mantenha uma camada de abstração (trait ToplevelWatcher) para que o shell não fique preso a um único compositor: a implementação via protocolos padrão cobre a maioria; a via IPC específica cobre extras.

Exemplo 8 — listar janelas (foreign toplevel)

Para a lista de janelas/workspaces na barra: o manager entrega um handle por janela, e a janela é um fluxo de eventos.

// Cargo.toml: wayland-protocols-wlr = { version = "0.3", features = ["client"] }
use wayland_protocols_wlr::foreign_toplevel::v1::client::{
    zwlr_foreign_toplevel_handle_v1::ZwlrForeignToplevelHandleV1,
    zwlr_foreign_toplevel_manager_v1::ZwlrForeignToplevelManagerV1,
};

// registry: bind "zwlr_foreign_toplevel_manager_v1" (confira com `wayland-info`)

impl Dispatch<ZwlrForeignToplevelManagerV1, ()> for App {
    fn event(state: &mut Self, _mgr: &ZwlrForeignToplevelManagerV1,
             event: zwlr_foreign_toplevel_manager_v1::Event,
             _: &(), _: &Connection, _: &QueueHandle<Self>) {
        match event {
            // nova janela: o manager entrega um handle
            ZwlrForeignToplevelManagerV1::Event::Toplevel { toplevel } => {
                state.janelas.insert(toplevel.clone(), Janela::default());
            }
            ZwlrForeignToplevelManagerV1::Event::Finished => state.running = false,
            _ => {}
        }
    }
}

impl Dispatch<ZwlrForeignToplevelHandleV1, ()> for App {
    fn event(state: &mut Self, handle: &ZwlrForeignToplevelHandleV1,
             event: zwlr_foreign_toplevel_handle_v1::Event,
             _: &(), _: &Connection, _: &QueueHandle<Self>) {
        match event {
            // título e app chegam como eventos separados:
            ZwlrForeignToplevelHandleV1::Event::Title { title } => { /* ... */ }
            ZwlrForeignToplevelHandleV1::Event::AppId { app_id } => { /* ... */ }
            ZwlrForeignToplevelHandleV1::Event::State { state: bits } => {
                // bits: 0=maximizada, 1=ativa, 2=fullscreen... (spec)
            }
            ZwlrForeignToplevelHandleV1::Event::Closed => {
                state.janelas.remove(&handle);
            }
            _ => {}
        }
    }
}
// ações (requests): handle.activate(&seat, &surface), close(),
// set_minimized(), set_maximized() — quando o compositor suportar
  • spec do wlr-foreign-toplevel-management — a lista de estados e requests
  • Verifique suporte: wayland-info | Sway/Hyprland também expõem IPC próprio — veja recursos

Exemplo 9 — lock screen (session lock)

// registry: bind "ext_session_lock_manager_v1" (wayland-protocols, feature "client")
use wayland_protocols::ext::session_lock::v1::client::{
    ext_session_lock_manager_v1::ExtSessionLockManagerV1,
    ext_session_lock_v1::{self, ExtSessionLockV1},
};

let manager: ExtSessionLockManagerV1 = /* bind do registry */;
let lock = manager.lock(qh, ());                       // pede o lock AGORA
let _lock_surface = lock.get_lock_surface(&surface, &output, qh, ());

impl Dispatch<ExtSessionLockV1, ()> for App {
    fn event(state: &mut Self, _lock: &ExtSessionLockV1,
             event: ext_session_lock_v1::Event,
             _: &(), _: &Connection, _: &QueueHandle<Self>) {
        match event {
            // compositor CONFIRMOU o lock — só AGORA a UI de senha aparece
            ext_session_lock_v1::Event::Locked => state.ui_pronta = true,
            // outro lock venceu / crash — destrua tudo e saia
            ext_session_lock_v1::Event::Finished => state.running = false,
            _ => {}
        }
    }
}
// PAM valida a senha (crate `pam` + crate `rpassword` p/ prompt) — ao sucesso:
// lock.unlock_and_destroy();

O par Locked/Finished é a resposta do protocolo às race conditions listadas acima: o compositor só oculta o conteúdo depois de confirmar o lock, e um cliente que perde o lock é notificado para se encerrar.

Exemplo 10 — idle detection

// registry: bind "ext_idle_notify_v1"
use wayland_protocols::ext::idle_notify::v1::client::ext_idle_notify_v1::{
    ExtIdleNotificationV1, ExtIdleNotifyManagerV1,
};

// 5 minutos em milissegundos, para o seat atual:
let notificacao: ExtIdleNotificationV1 =
    manager.get_idle_notification(5 * 60 * 1000, &seat, qh, ());

// eventos desta interface:
//   Idle    -> sem interação pelo timeout: envie Evento::Idle no bus
//              (módulos decidem: lock screen + DPMS)
//   Resumed -> usuário voltou a interagir

Aplicativos pedem para prevenir o idle (vídeo tocando, download…) com o protocolo zwp_idle_inhibit_manager_v1. Seu shell deve respeitar o inhibitor antes de disparar lock/DPMS — pesquise "idle inhibit" na spec do wayland-protocols.

Exemplo 11 — launcher: parsear .desktop files

Um parser mínimo de Desktop Entry (para aprender; em produção use o crate freedesktop-desktop-entry):

use std::fs;

#[derive(Debug, Default)]
struct DesktopEntry {
    nome: String,
    exec: String,
    icone: String,
    terminal: bool,
    oculto: bool,
}

fn parse_entry(texto: &str) -> Option<DesktopEntry> {
    let mut entry = DesktopEntry::default();
    let mut secao_correta = false;

    for linha in texto.lines() {
        let linha = linha.trim();
        if linha.starts_with('[') {
            secao_correta = linha == "[Desktop Entry]";
        } else if secao_correta {
            if let Some((chave, valor)) = linha.split_once('=') {
                match chave.trim() {
                    "Name" => entry.nome = valor.to_string(),
                    "Exec" => entry.exec = valor.to_string(),
                    "Icon" => entry.icone = valor.to_string(),
                    "Terminal" => entry.terminal = valor == "true",
                    "Hidden" | "NoDisplay" => entry.oculto |= valor == "true",
                    _ => {}
                }
            }
        }
    }
    (!entry.nome.is_empty() && !entry.exec.is_empty() && !entry.oculto)
        .then_some(entry)
}

// onde procurar, segundo o XDG Base Directory spec:
fn diretorios_de_apps() -> Vec<std::path::PathBuf> {
    let home = std::env::var("XDG_DATA_HOME").unwrap_or_else(|_|
        format!("{}/.local/share", std::env::var("HOME").unwrap_or_default()));
    let sistema = std::env::var("XDG_DATA_DIRS")
        .unwrap_or_else(|_| "/usr/local/share:/usr/share".into());

    std::iter::once(home)
        .chain(sistema.split(':').map(String::from))
        .map(|d| std::path::PathBuf::from(d).join("applications"))
        .collect()
}
  • Exercício imediato: rode este código contra os .desktop reais do seu sistema (ls ~/.local/share/applications).
  • Faltam os casos que a spec exige: nomes localizados (Name[pt_BR]=), códigos de campo no Exec (%f, %u) e parsing seguro dos argumentos — por isso o crate pronto vale o estudo.
  • Executar: std::process::Command com o binário do Exec — nunca via sh -c com a string crua.
  • Desktop Entry Spec — tabela de chaves e o formato do Exec
  • XDG Base Directory Spec — de onde vêm os diretórios
  • crate freedesktop-desktop-entry — parser completo e mantido
