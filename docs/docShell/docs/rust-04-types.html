Structs, enums, traits e pattern matching

Java junta tudo em classes. Rust desmembra: dados em struct, variantes em enum, comportamento em trait, e match amarra tudo. Sem herança de implementação.

Structs — dados (≈ classes sem herança)

pub struct Usuario {
    pub nome: String,
    pub ativo: bool,
    pub email: String,
}

impl Usuario {
    // função associada (≈ static factory) — convenção: `new`
    pub fn new(nome: String, email: String) -> Self {
        Self { nome, ativo: true, email }
    }

    // método de leitura (&self = emprestado)
    pub fn email_curto(&self) -> &str {
        self.email.split('@').next().unwrap_or("")
    }

    // método de mutação (&mut self)
    pub fn desativar(&mut self) {
        self.ativo = false;
    }
}
Java 
class Usuario {
    private String nome;
    private boolean ativo;

    Usuario(String nome) {
        this.nome = nome;
        this.ativo = true;
    }

    void desativar() {
        this.ativo = false;
    }
}
Rust 
struct Usuario {
    nome: String,
    ativo: bool,
}

impl Usuario {
    fn new(nome: String) -> Self {
        Self { nome, ativo: true }
    }

    fn desativar(&mut self) {
        self.ativo = false;
    }
}

O primeiro parâmetro dos métodos é sempre self explícito: &self (ler), &mut self (mutar), self (consumir). A ownership que você aprendeu no capítulo anterior se aplica a self também.

Syntax sugar útil:

// atualizar baseado no valor antigo (struct update syntax)
let admin = Usuario { nome: String::from("root"), ..u1 };
// note: u1.email é MOVIDO para admin, o resto é copiado

Enums — variantes com dados

Enums em Rust são muito mais fortes que os de Java: cada variante pode carregar dados próprios.

enum Forma {
    Circulo(f64),                        // variante com um valor
    Retangulo { largura: f64, altura: f64 },  // variante com campos
    Ponto,                               // variante sem dados
}

enum Mensagem {
    Sair,
    Mover { x: i32, y: i32 },
    Escrever(String),
    MudarCor(u8, u8, u8),
}

Em Java moderno isso seria uma sealed interface + records. Em Rust é o elemento central do sistema de tipos: Option<T> e Result<T, E> — que você usará o tempo todo — são enums da biblioteca padrão.

match — o switch definitivo

fn area(f: &Forma) -> f64 {
    match f {
        Forma::Circulo(r) => 3.14159 * r * r,
        Forma::Retangulo { largura, altura } => largura * altura,
        Forma::Ponto => 0.0,
    }
}

fn processar(msg: Mensagem) {
    match msg {
        Mensagem::Sair => println!("tchau"),
        Mensagem::Mover { x, y } => println!("mover p/ ({x},{y})"),
        Mensagem::Escrever(txt) if txt.len() > 10 => println!("texto longo: {txt}"),
        Mensagem::Escrever(txt) => println!("texto: {txt}"),
        Mensagem::MudarCor(r, g, b) => println!("cor rgb({r},{g},{b})"),
    }
}
  • Exaustivo: o compilador exige cobrir todas as variantes (o curinga _ existe, mas evite abuse — troque por outra => para capturar).
  • Faz destructuring e binding de dados internos.
  • Aceita guards (if depois do padrão).
  • Funciona com números, tuplas, enums, structs, Option, Result.

Atalhos para casos únicos:

if let Mensagem::Escrever(txt) = msg {
    println!("{txt}");
}

Traits — comportamento (≈ interfaces)

trait Resumivel {
    fn resumo(&self) -> String;      // obrigatório

    fn anuncio(&self) -> String {     // com implementação default
        format!("Confira: {}", self.resumo())
    }
}

struct Artigo { titulo: String, autor: String }

impl Resumivel for Artigo {
    fn resumo(&self) -> String {
        format!("{} por {}", self.titulo, self.autor)
    }
}

struct Video { titulo: String }

impl Resumivel for Video {
    fn resumo(&self) -> String {
        format!("Video: {}", self.titulo)
    }
}

Diferenças para interfaces Java: traits podem ter métodos default (ok, igual), podem ser implementadas para qualquer tipo — até tipos de fora (como impl Display for MeuTipo), e não há herança de estado.

Trait bounds (generics com contrato)

use std::fmt::Display;

fn notificar(item: &impl Display) {         // aceita qualquer tipo Display
    println!("novidade: {item}");
}

// forma longa equivalente (generics):
fn notificar2<T: Display>(item: &T) { ... }

// múltiplos bounds:
fn salvar<T: Display + Clone>(item: &T) { ... }

Diferente de Java, não há type erasure: o compilador gera código especializado para cada T (monomorphization) — polimorfismo sem custo, tudo resolvido em compilação. Para polimorfismo em runtime (como uma referência de interface em Java), existe dyn Trait — ver adiante.

Derive — o "Lombok" do Rust

#[derive(Debug, Clone, PartialEq)]
struct Ponto { x: i32, y: i32 }

// Debug     -> println!("{:?}", p)        (≈ toString)
// Clone     -> p.clone()                  (cópia profunda)
// PartialEq -> p == q                     (≈ equals)
// Default   -> Ponto::default()

Sem herança — e agora?

Rust não tem extends. As ferramentas são:

  • Composição: structs contêm structs. Resolve 90% dos casos onde você usaria herança.
  • Traits compartilhados: comportamento comum via trait + bounds.
  • dyn Trait (trait objects): quando precisa de coleção heterogênea, como List<Interface> em Java: 
    let itens: Vec<Box<dyn Resumivel>> = vec![
    Box::new(artigo),
    Box::new(video),
];
for i in &itens {
    println!("{}", i.resumo());   // dispatch dinâmico, como Java
}

Exercícios

  1. Crie enum StatusTarefa { Pendente, EmProgresso { percentual: u8 }, Concluida(String) } e uma função que descreve cada estado via match.
  2. Trait Area com fn area(&self) -> f64; implemente para Circulo e Retangulo; some as áreas de um Vec<Box<dyn Area>>.
  3. Struct Tempo { horas: u8, minutos: u8 } com impl Display (trait da std) para imprimir 09:05.
  4. Função genérica fn maximo<T: PartialOrd>(v: &[T]) -> Option<&T>.
