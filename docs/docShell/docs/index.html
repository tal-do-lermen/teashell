Desktop Shell Wayland em Rust

Um guia de aprendizado para quem já programa em Java ou JavaScript e quer aprender Rust do zero construindo um projeto real: um desktop shell para Wayland.

O projeto

Construir um desktop shell modular — barra, launcher, notificações, lock screen, dock, wallpaper, control center, widgets, configuração e IPC — executando sobre um compositor Wayland existente como Sway, Hyprland ou Niri.

O shell é um cliente Wayland, não um compositor. Isso reduz drasticamente o escopo: você não vai lidar com DRM/KMS, drivers de GPU ou gerenciamento de janelas em baixo nível. O foco é aprender Rust resolvendo problemas reais de sistema.

Como usar este guia

  1. Parte 1 — Rust do zero (páginas 01–09): fundamentos da linguagem com comparações diretas a Java e JS. Estude nesta ordem, com o editor aberto, digitando e executando cada exemplo.
  2. Parte 2 — O roadmap do shell (páginas 10–17): o que pesquisar e em qual ordem para construir o shell. Cada página contém exemplos de código comentados e caixas "Onde buscar as infos" com a fonte oficial de cada tema. A página final (Roadmap de implementação) organiza tudo em 14 fases.
  3. Volte às páginas da Parte 2 como referência conforme avança nas fases. Não tente ler tudo antes de escrever código.

Regra de ouro para quem já sabe programar: escreva código desde o dia 1. Use Rustlings em paralelo com as páginas da Parte 1. A linguagem cobra prática — o borrow checker não se aprende só lendo.

Mapa do guia

Parte 1 — Rust do zero

  1. Configuração do ambiente e Cargo
    rustup, cargo vs npm/Maven, hello world, editor
  2. Fundamentos: variáveis, tipos e funções
    imutabilidade, tipos primitivos, &str vs String, expressões
  3. Ownership, borrowing e lifetimes
    o capítulo mais importante — memória sem garbage collector
  4. Structs, enums, traits e pattern matching
    o "OOP de Rust": dados, comportamento e polimorfismo
  5. Tratamento de erros: Option, Result e o operador ?
    erros como valores, thiserror e anyhow
  6. Coleções, closures e iterators
    Vec, HashMap, iteradores vs Streams/Array methods
  7. Concorrência: threads, Arc, Mutex e channels
    data races eliminadas em tempo de compilação
  8. Async/await e Tokio
    futures lazy, runtime Tokio, join!/select! vs Promise.all
  9. Módulos, crates, logging e testes
    organização de projetos, tracing, cargo test

Parte 2 — Roadmap do shell

  1. Wayland: fundamentos e Rust
    protocolo, globals, surfaces, event queue, wayland-client
  2. Layer Shell
    como a barra ocupa o topo da tela — o coração do shell
  3. Rendering, UI Toolkit e Input
    wgpu, iced/slint/egui, pointer e keyboard
  4. Arquitetura interna
    event loop, message bus, módulos, estrutura do projeto
  5. D-Bus e serviços do sistema
    notificações, áudio (PipeWire), rede, bluetooth, energia, brilho
  6. Componentes do shell
    launcher, janelas/workspaces, lock screen, idle, wallpaper, multi-monitor
  7. Configuração, IPC e performance
    TOML + hot reload, unix socket, profiling
  8. Roadmap de implementação
    14 fases, o que NÃO estudar primeiro, recursos oficiais

Pré-requisitos

  • Conhecimento sólido de pelo menos uma linguagem (Java, JS) — orientação a objetos, coleções, concorrência básica.
  • Linux instalado (recomenda-se testar num ambiente com Sway/Hyprland/Niri, ou até uma VM) — o alvo final é Wayland.
  • Não é preciso saber Rust. Nada de C/C++ é assumido.

Resultado esperado

Ao terminar a pesquisa, você deve conseguir explicar sem consultar código:

  1. Como um cliente Wayland se conecta ao compositor.
  2. Como descobre globals.
  3. Como cria uma surface.
  4. Como transforma uma surface em layer-shell.
  5. Como recebe input.
  6. Como renderiza.
  7. Como sincroniza frames.
  8. Como detecta mudanças de estado.
  9. Como conversa com D-Bus.
  10. Como controla áudio/rede/Bluetooth/energia.
  11. Como encontra aplicações .desktop.
  12. Como acompanha janelas/workspaces.
  13. Como implementa lock screen.
  14. Como monitora idle.
  15. Como gerencia múltiplos monitores.
  16. Como mantém configuração.
  17. Como cria IPC.
  18. Como mede e otimiza performance.

Só depois disso vale começar a montar a implementação completa.

O que NÃO estudar primeiro: Smithay internals, DRM/KMS, implementação de compositor, XWayland, wlroots internals, desenvolvimento de drivers de GPU. São temas centrais para construir um compositor — não para o primeiro estágio de um shell. Detalhes na página do roadmap.
