Fundamentos: variáveis, tipos e funções

A sintaxe é familiar, mas a semântica tem diferenças que fazem diferença. Foco nas que mais confundem quem vem de Java/JS.

Variáveis: imutáveis por padrão

Em Rust, toda variável é imutável a menos que você escreva mut. É o inverso de Java/JS.

Java 
int x = 5;          // mutável
final int y = 10;   // imutável
x = 6;              // ok
y = 11;             // erro de compilação
Rust 
let x = 5;          // imutável
let mut y = 10;     // mutável
x = 6;              // erro de compilação
y = 11;             // ok

const em JS só impede reatribuição do binding (o objeto interno continua mutável). let sem mut em Rust impede qualquer mutação através daquele binding. É o final de Java, mas como padrão da linguagem e verificado a fundo pelo compilador.

Shadowing

Você pode declarar uma nova variável com o mesmo nome, substituindo a anterior — inclusive mudando o tipo:

let espacos = "   ";
let espacos = espacos.len();   // agora é um número (usize)

let idade = "30";
let idade: u32 = idade.parse().expect("não é número");  // str -> u32

Em Java isso não compila no mesmo escopo; em Rust é idiomático para transformações em sequência (conversões de tipo, parsing), evitando nomes como idadeStr, idadeNum.

Overflow de inteiro: em modo debug (cargo run), overflow panica (o programa aborta com erro). Em modo release, faz wrap (comporta-se como Java). Isso evita bugs silenciosos durante o desenvolvimento.

Strings: a primeira pegadinha

Rust tem dois tipos de string, e entender a diferença agora poupa muita dor:

let s1: &str   = "texto literal";       // view imutável para dados em memória
let s2: String = String::from("texto");  // string alocada no heap, crescível

let mut s3 = String::from("ola");
s3.push_str(", mundo");                  // só String cresce

// conversões frequentes:
let s4: &str = &s3;                     // String -> &str (barato, sem cópia)
let s5: String = s1.to_string();         // &str -> String (aloca)
Java 
String s = "ola";          // imutável no heap
StringBuilder sb = ...;    // crescível
// uma só mentalidade: tudo é objeto referenciado
// pelo GC
Rust 
let s = "ola";             // &str: emprestado
let mut s = String::from("ola");  // dono do heap
// escolha depende de quem POSSUI os
// dados — ver capítulo de ownership

Regra prática de iniciante: literais e parâmetros de leitura usam &str; strings que você constrói/modifica usam String.

Funções

Java 
static int soma(int a, int b) {
    return a + b;
}
Rust 
fn soma(a: i32, b: i32) -> i32 {
    a + b            // sem `return` nem `;`
}
  • Tipos dos parâmetros e do retorno são obrigatórios.
  • A última expressão (sem ;) é o valor de retorno. Colocar ; ali é a pegadinha clássica: o compilador avisará "expected i32, found ()".
  • Convenção: snake_case para funções e variáveis.

Controle de fluxo: tudo é expressão

Blocos como if e {} produzem valores — sem ternário necessário:

let n = if condicao { 5 } else { 10 };

let msg = {
    let x = 3;
    x * x            // valor do bloco: 9
};

// loop pode retornar valor via break:
let mut contador = 0;
let resultado = loop {
    contador += 1;
    if contador == 10 {
        break contador * 2;    // loop "retorna" 20
    }
};

if exige bool de verdade — não existe truthiness como em JS. if (valor) não compila; escreva if valor != 0.

Loops:

// for sobre ranges (0..5 = 0,1,2,3,4 | 0..=5 inclui o 5)
for i in 0..5 {
    println!("{i}");
}

// while tradicional
let mut n = 3;
while n != 0 {
    n -= 1;
}
