Tratamento de erros: Option, Result e o operador ?

Java e JS usam exceptions. Rust não tem exceptions: erros são valores de retorno, e o sistema de tipos te obriga a lidar com eles. Só existe o ? entre você e o erro.

Option<T> — a morte do null

Não existe null em Rust. Ausência de valor é um tipo:

enum Option<T> {
    Some(T),   // tem valor
    None,      // não tem
}
Java 
String nome = mapa.get("chave");  // pode ser null!
if (nome != null) { ... }
// Optional existe, mas é opcional
// NullPointerException à distância
Rust 
let nome = mapa.get("chave");     // Option<&str>
match nome {
    Some(n) => println!("{n}"),
    None => println!("não achou"),
}
// impossível esquecer: o compilador cobra

Ferramentas do dia a dia (equivalentes ao Optional de Java):

let cfg = mapa.get("tema");

let tema = cfg.unwrap_or("escuro");              // com fallback
let tema = cfg.expect("config obrigatória");     // panica com mensagem (use pouco)
if let Some(t) = cfg { ... }                     // só o caso Some
cfg.map(|t| t.to_uppercase());                   // ≈ Optional.map
cfg.and_then(validar);                           // ≈ Optional.flatMap

Result<T, E> — exceptions como valores

enum Result<T, E> {
    Ok(T),   // sucesso, com o valor
    Err(E),  // falha, com o erro
}
Java (exceptions)Rust (Result)
throw new IOException(...)return Err(e.into())
catch (IOException e) { ... }match r { Ok(v) => ..., Err(e) => ... }
checked exception na assinatura-> Result<T, MeuErro> — e aqui é enforced de verdade
exception não tratada explode em runtimeResult ignorado gera warning e o erro propaga explicitamente

O operador ? — propagação de erro

O ? significa: "se for Err, retorne agora o erro; se for Ok, extraia o valor e siga".

Java 
String lerConfig() throws IOException {
    var path = Path.of("app.toml");
    var conteudo = Files.readString(path);
    return conteudo.trim();
}
// exceção explode para cima
// invisível no corpo do método
Rust 
fn ler_config() -> Result<String, std::io::Error> {
    let conteudo = std::fs::read_to_string("app.toml")?;
    Ok(conteudo.trim().to_string())
}
// cada `?` pode abortar a função
// com o erro — explícito e rastreável

Um main também pode retornar Result:

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let cfg = std::fs::read_to_string("app.toml")?;
    println!("{cfg}");
    Ok(())
}

panic! — o "Error" de Rust

panic! aborta o programa (como uma RuntimeException não capturada). Regras:

  • Use para bugs e invariantes violadas — nunca para fluxo esperado (arquivo pode não existir? então é Result).
  • .unwrap() panica se for Err/None — só em protótipos e testes.
  • .expect("msg") — igual, mas explica por quê. Aceitável quando você prova que não falha.

thiserror — erros de biblioteca/módulo

Quando você define seus próprios erros, o crate thiserror elimina o boilerplate:

use thiserror::Error;

#[derive(Debug, Error)]
pub enum ShellError {
    #[error("config inválida: {0}")]
    Config(#[from] toml::de::Error),

    #[error("falha de E/S: {0}")]
    Io(#[from] std::io::Error),

    #[error("canal {canal} não encontrado")]
    Canal { canal: String },
}

Equivalente a criar classes de exception em Java — #[from] permite que o ? converta erros de outros tipos automaticamente (o try-with-resources de conversão que o Java nunca teve).

anyhow — erros de aplicação

No nível da aplicação (o main), onde você só quer logar o erro e sair, o crate anyhow dá um erro "qualquer coisa" com contexto:

use anyhow::{Context, Result};

fn iniciar() -> Result<()> {
    let cfg = std::fs::read_to_string("shell.toml")
        .context("lendo shell.toml")?;       // adiciona contexto ao erro
    let config = parse(&cfg)
        .context("parseando shell.toml")?;
    // ...
    Ok(())
}

Regra de bolso para o projeto do shell: thiserror em módulos/crates (erros tipados que os chamadores podem tratar), anyhow no binário principal (onde erro = log e sair). É o fluxo idiomático do ecossistema.

Exercícios

  1. Escreva fn dividir(a: f64, b: f64) -> Result<f64, String> retornando Err para divisão por zero; use ? numa função que encadeia três divisões.
  2. Leia um arquivo inexistente com std::fs::read_to_string e trate com match; depois refatore usando ? + main -> Result.
  3. Crie um enum ErroParse com thiserror e escreva fn parse_idade(s: &str) -> Result<u8, ErroParse> convertendo o erro de parse::<u8> com #[from].
  4. Use .context() de anyhow nas chamadas da função anterior.
