Layer Shell

Esta é uma das partes mais importantes para o shell: é o mecanismo que permite à barra dizer ao compositor "quero ficar colada no topo, em todas as telas".

O que pesquisar

  • wlr-layer-shell — a extensão do protocolo (originada no wlroots, adotada por Sway/Hyprland/Niri)
  • zwlr_layer_shell_v1 — o objeto global da extensão
  • zwlr_layer_surface_v1 — a surface especial do shell
  • Layer surfaces

A conversa com o compositor

Entenda como uma barra informa suas intenções:

"quero ficar no topo"
"quero ocupar esta área"
"quero reservar espaço para outros aplicativos"

Traduzindo para os conceitos do protocolo:

  • Anchor — em quais bordas a surface gruda (top, bottom, left, right). Anchor em duas bordas opostas + exclusive zone = barra full-width.
  • Margin — distância das bordas ancoradas.
  • Exclusive zone — quantos pixels o compositor deve reservar para você (janelas de apps não cobrem nem ficam por baixo da barra).
  • Keyboard interactivity — none (barra), exclusive (launcher/lock), on-demand.
  • Output — em qual monitor a surface nasce (ou all).
  • Namespace — identificador string (ex.: "myshell/bar") usado por compositores para regras por-surface.

Janela normal vs layer surface vs popup vs subsurface

Pesquise também as diferenças entre:

Em Rust, a extensão fica em wayland-protocols-wlr (crate) — o tipo Shell/LayerSurface embrulha zwlr_layer_surface_v1. Estude os exemplos de layer-shell do repositório wayland-rs antes de tentar do zero.

Exemplo 2 — a barra com layer shell

O código que materializa aquela conversa "quero ficar no topo": binds da extensão, configuração da layer surface e o ciclo configure → ack → render.

// Cargo.toml:
// [dependencies]
// wayland-client = "0.31"
// wayland-protocols-wlr = { version = "0.3", features = ["client"] }

use wayland_client::{
    protocol::{wl_compositor, wl_registry, wl_surface},
    Connection, Dispatch, QueueHandle,
};
use wayland_protocols_wlr::layer_shell::v1::client::{
    zwlr_layer_shell_v1::{Layer, ZwlrLayerShellV1},
    zwlr_layer_surface_v1::{self, Anchor, KeyboardInteractivity, ZwlrLayerSurfaceV1},
};

struct App {
    running: bool,
    compositor: Option<wl_compositor::WlCompositor>,
    layer_shell: Option<ZwlrLayerShellV1>,
}

// registry: descubra os DOIS globals que a barra precisa
impl Dispatch<wl_registry::WlRegistry, ()> for App {
    fn event(state: &mut Self, registry: &wl_registry::WlRegistry, event: wl_registry::Event,
             _: &(), _: &Connection, qh: &QueueHandle<Self>) {
        if let wl_registry::Event::Global { name, interface, version } = event {
            match interface.as_str() {
                "wl_compositor" => {
                    state.compositor = Some(registry.bind::<wl_compositor::WlCompositor, _, _>(
                        name, version.min(4), qh, ()));
                }
                "zwlr_layer_shell_v1" => {
                    state.layer_shell = Some(registry.bind::<ZwlrLayerShellV1, _, _>(
                        name, version.min(4), qh, ()));
                }
                _ => {}
            }
        }
    }
}

impl App {
    fn montar_barra(&self, qh: &QueueHandle<Self>) {
        let compositor = self.compositor.as_ref().expect("sem wl_compositor");
        let shell = self.layer_shell.as_ref().expect("compositor sem layer-shell");

        let surface: wl_surface::WlSurface = compositor.create_surface(qh);

        let layer_surface: ZwlrLayerSurfaceV1 = shell.get_layer_surface(
            &surface,
            None,                    // None = em TODOS os monitores
            Layer::Top,              // camada da barra (veja a tabela acima)
            "meushell/bar".into(),   // namespace
            qh,
            (),
        );

        // "quero ficar no topo, ocupando toda a largura"
        layer_surface.set_anchor(Anchor::TOP | Anchor::LEFT | Anchor::RIGHT);
        // "reservem 32px para mim — nada pode cobrir esta área"
        layer_surface.set_exclusive_zone(32);
        // barra não digita: teclado só sob demanda
        layer_surface.set_keyboard_interactivity(KeyboardInteractivity::None);
        // largura 0 = "esticar entre os anchors"; altura 32
        layer_surface.set_size(0, 32);

        // publica a surface — agora o compositor responde com Configure
        surface.commit();
    }
}

// o ciclo obrigatório: compositor propõe o tamanho -> você confirma -> desenha
impl Dispatch<ZwlrLayerSurfaceV1, ()> for App {
    fn event(_state: &mut Self, layer_surface: &ZwlrLayerSurfaceV1,
             event: zwlr_layer_surface_v1::Event, _: &(), _: &Connection, _: &QueueHandle<Self>) {
        if let zwlr_layer_surface_v1::Event::Configure { serial, .. } = event {
            layer_surface.ack_configure(serial);   // OBRIGATÓRIO antes de desenhar
            // ... aqui entra o renderer (Exemplo 3)
            println!("barra configurada — hora de renderizar");
        }
    }
}

Pontos de atenção:

  • set_size(0, 32) — zero significa "o compositor decide" (derivado dos anchors). O valor real chega no Configure.
  • set_exclusive_zone(32) é o que impede janelas de apps de ficarem atrás da barra. Para o wallpaper, use -1 (ignora exclusive zones).
  • Desenhar sem ter feito ack_configure é erro de protocolo — o compositor pode matar seu cliente.
  • Nomes de módulos gerados variam entre versões do crate — quando algo não compila, a fonte da verdade é o docs.rs da versão no seu Cargo.toml.
  • spec do wlr-layer-shell-unstable-v1 — leia os requests de zwlr_layer_surface_v1: é a lista exata do que dá para configurar
  • docs.rs/wayland-protocols-wlr
  • exemplos do client-toolkit (sctk) — o sctk embrulha tudo isso em tipos de alto nível (LayerSurface, com attach de buffers incluso)
